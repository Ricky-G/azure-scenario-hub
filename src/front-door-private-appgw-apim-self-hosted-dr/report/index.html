The verdict

PASS · PRIVATE MANAGED PATH

/happy/* remained private after Front Door

Front Door used Private Link to the Application Gateway private listener. Application Gateway then reached APIM Premium in internal VNet mode, and managed APIM reached the shared AKS backend through an internal load balancer.

PASS · SELF-HOSTED DR PATH

/dr/* reached the APIM self-hosted gateway

Front Door selected the AKS public origin, the subnet NSG admitted only Front Door origin traffic and load-balancer probes, and the APIM self-hosted gateway routed to the same backend over cluster-local DNS.

Engineering findings

Private does not mean public-IP-free here

Application Gateway Private Link is not currently supported with the enhanced private-only gateway mode. The template therefore creates a public frontend required by the platform but attaches no listener or routing rule to it.

DR proof needs both planes

A response header proves the self-hosted data plane served the request. A scoped managed-identity ARM read separately proves the gateway is registered to central APIM and owns dr-api.

Subnet policy decides origin reachability

The DR origin regressed when a delayed default-deny subnet NSG blocked Front Door before the request reached the Kubernetes service. The scenario now owns that NSG and permits only Azure Front Door backend traffic on port 80 plus load-balancer probes.

Operational recovery evidence

Stopped origins look like routing failures

During follow-up validation, Application Gateway and AKS were both found stopped while their configuration remained intact. The recovery scripts now restore only stopped resources, wait for Application Gateway Running and AKS Running/Succeeded, and the test suite checks those states before making data-plane assertions. The available evidence is consistent with lab cost-control automation; it does not identify a specific caller.

Security posture and proof boundaries

Controls demonstrated

  • Front Door and Application Gateway WAF policies run in prevention mode.
  • The happy listener is private and reachable through Front Door Private Link.
  • APIM Premium is injected in internal VNet mode.
  • DR ingress is subnet-restricted to Azure Front Door backend traffic.
  • The backend runs non-root with dropped capabilities and a read-only root filesystem.
  • ARM evidence uses managed identity with Reader scoped only to APIM.

Not claimed by this POC

  • The two explicit paths are not automatic health-based failover.
  • AKS models on-premises Kubernetes; it is not a separate physical site.
  • The DR origin uses HTTP for transparent lab validation.
  • A one-node cluster and single APIM region are not resilient production topology.
  • The 29-day self-hosted gateway token is not the recommended production identity model.
  • The report contains captured proof, not continuous health evidence.
